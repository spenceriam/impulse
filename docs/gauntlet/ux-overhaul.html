Coding runtime UX overhaul

Branch: fix/formatting-and-tool-guardrails-127-128

Goal

Make Impulse polished enough for other developers to adopt: a coherent terminal coding runtime with clear prompts, streaming responses, thinking, tools, permissions, planning, settings, skills, density controls, and ACP interoperability.

Concrete bar

Grok Build Judge interaction hierarchy, compactness, state legibility, plan review, permission flow, tool presentation, and progressive disclosure against the running product, official examples, and public TUI source.
Pi / pi-tui Preserve differential rendering, keyboard-first behavior, terminal-width resilience, and the deliberately small visual vocabulary of the underlying TUI foundation.
ACP v1 Prove interoperability with protocol-level fixtures for initialization, sessions, prompt streaming, tool calls, permissions, plans, modes, config options, a truthful command surface, cancellation, and terminal/file-system capabilities.
  • Token-firehose probe: typing, navigation, queueing, cancellation, and resize remain responsive while stable Markdown does not oscillate.
  • Thinking probe: immediate activity, bounded live content, elapsed-time collapse, full expansion, and replay without empty or zero-duration blocks.
  • Tool probe: semantic collapsed rows, grouped read/search activity, reversible truncation, and useful edit diffstats.
  • Permission probe: exact operation and scope, safe initial focus, park-without-answer, rejection feedback, and long-content resilience.
  • Discovery probe: bounded fuzzy slash results, no alias duplicates, contextual availability, completion without accidental execution, and a dedicated skills submenu.
  • Short-terminal probe: preserve prompt, transcript, and blocking decisions before chrome; temporary auto-compaction must not overwrite the user's density preference.

Loop contract

  1. The lead splits the goal into the smallest independently improvable and judgeable pieces.
  2. Each piece receives a builder with the goal, rules, and bar.
  3. A separate fresh-context critic inspects the real artifact, not the builder's summary.
  4. If Impulse loses the comparison, the critic identifies the largest meaningful gap.
  5. The builder fixes that gap and the piece returns to a fresh critic. There is no fixed round count.
  6. After each major wave, a fresh smoothing agent checks the complete runtime for consistency.

Sandbox comparison bar

Separate controls Mode governs agent behavior, approval policy governs consent prompts, and the execution boundary governs technical capability. No label or Allow-All setting may be presented as sandboxing.
Fail closed Probe the host backend before advertising isolation. An unavailable or failed sandbox must stop the isolated action or require an explicit, accurately labeled host-execution choice.
Layered preview A safe preview combines an isolated Git worktree with an OS-enforced filesystem and network boundary. The worktree makes the diff reviewable; the sandbox protects the machine.
  • Codex uses platform backends: Seatbelt on macOS, Bubblewrap with a Landlock fallback on Linux, and restricted-token sandboxing on Windows.
  • Codex workspace-write keeps the filesystem read-only by default, layers explicit writable roots, and protects repository metadata such as .git.
  • Copilot exposes OS sandboxing and Git worktrees as separate features, reinforcing that neither substitutes for the other.
  • Impulse must test filesystem escape, network denial, process cleanup, symlink traversal, protected repository metadata, unsupported hosts, and truthful fallback messaging.

ACP readiness bar

Current assessment: stable-v1 launch bar met. The TUI and ACP adapter now consume the same session-scoped runtime; ACP stdio remains JSON-RPC-pure and advertises only implemented behavior.

  • A session-scoped runtime must own cwd, mode, history, permissions, elicitation, tools, active processes, and cancellation.
  • Two interleaved sessions must remain independent, including cancellation and permission responses.
  • The ACP process must keep stdout JSON-RPC-pure and send diagnostics only to stderr.
  • Fixture transcripts must cover initialization, lifecycle, content capabilities, prompt streaming, tools and permissions, elicitation, plans and config, cancellation, and optional client filesystem/terminal capabilities.
  • Only implemented capabilities may be advertised; resource links and stdio MCP setup are baseline launch requirements.
